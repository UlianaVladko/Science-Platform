# Научный атлас — витрина фронтенда

Демонстрационный фронтенд команды UI («самые красивые и креативные») для учебного
проекта «Научный атлас: научная литература как связный граф».

Стек: **React 19 + TypeScript + Vite 7**, графики — **ECharts 6**, графы — **d3-force**,
BFF — **Go 1.22** на стандартной библиотеке (без внешних зависимостей).

## Что внутри

```
.
├── compose.yaml          # docker compose: web + bff (+ api в профиле full)
├── api.Dockerfile        # образ согласованного API (vendor/literature-api)
├── CONTRACT.md           # контракт BFF ↔ фронтенд по всем экранам
├── bff/                  # Go BFF: 3 источника данных, синтетический корпус, состояние в памяти
├── vendor/literature-api # копия API команды API (FastAPI, 20 операций)
├── web/                  # React-приложение
└── scripts/go_sanity.py  # статическая проверка Go-кода без тулчейна
```

### Три источника данных

| Источник | Что даёт | Как помечен в UI |
| --- | --- | --- |
| `api` | Согласованный API (20 операций): каталог, поиск, карточки, авторы, аналитика | бейдж **API** |
| `demo` | Синтетический корпус BFF: 218 публикаций, 64 автора, 15 дисциплин, детерминированный (seed 2026-11-18) | бейдж **демо** |
| `bff` | То, чего нет в контракте API: Q&A, лайки, подписки, факты по направлениям, 21 виджет дашборда | бейдж **BFF** |

Каждая сущность и каждый виджет несут поле `source`, поэтому витрина никогда не
выдаёт демо-данные за реальные. Если API недоступен, поиск продолжает работать по
демо-корпусу и показывает честную плашку «API недоступен».

### Экраны

- **Главная** — hero, быстрый поиск, KPI корпуса, карточки наук с фактами при наведении, топ публикаций.
- **Поиск** — режимы гибрид/точно/смысл, фасеты, фильтры по направлению/языку/типу/годам, подсветка совпадений.
- **Публикация** — метаданные, аннотация, ключевые слова и понятия, библиография в обе стороны, похожие работы, лайк, просмотры, файлы.
- **Автор** — профиль, статистика, динамика по годам, список публикаций, граф соавторства, подписка.
- **Аналитика** — 21 виджет (таймлайны, доли, топы, облако слов, тепловая карта, граф цитирований); виджеты, зависящие от NLP, показывают состояние «Данные готовятся».
- **Вопросы** — список, создание вопроса, карточка вопроса с ответами и голосами.
- **Добавить** — подстановка метаданных по DOI/названию и создание карточки.

## Запуск на целевой машине

Требуется Docker 24+ с плагином compose.

### 1. Основной сценарий: демо на демо-корпусе

```bash
cd science-platform
docker compose up --build
```

- Витрина: <http://localhost:8088>
- BFF напрямую: <http://localhost:8080/api/health>

Сервис `bff` поднимется первым (healthcheck), затем `web`. Фронтенд собран
статикой в nginx, `/api` проксируется на BFF.

### 2. Полный сценарий: вместе с согласованным API

```bash
docker compose --profile full up --build
```

Тогда `bff` получит `UPSTREAM_URL=http://api:8000`, и поиск/каталог/аналитика будут
подмешивать данные из настоящего API. Ответы поиска объединяются, дубликаты
убираются, фасеты сливаются, в ответе появляется флаг `degraded`.

Если API отдаёт ошибку или не стартовал — ничего не ломается, витрина остаётся на
демо-корпусе.

### 3. API уже запущен на хосте

```bash
UPSTREAM_URL=http://host.docker.internal:8000 docker compose up --build
```

### 4. Локальная разработка без Docker

Нужны Go 1.22+ и Node 20+.

```bash
# терминал 1 — BFF
cd bff
UPSTREAM_URL=http://127.0.0.1:8000 go run ./cmd/server

# терминал 2 — фронтенд с проксированием /api на BFF
cd web
npm ci
npm run dev          # http://localhost:5173
```

Проверки:

```bash
cd web && npm run build     # tsc -b && vite build
cd web && npm run lint      # tsc --noEmit
cd bff && go vet ./... && go build ./...
python3 scripts/go_sanity.py
```

### Переменные окружения BFF

| Переменная | По умолчанию | Смысл |
| --- | --- | --- |
| `PORT` | `8080` | порт BFF |
| `UPSTREAM_URL` | `http://127.0.0.1:8000` | адрес согласованного API |
| `SYNTHETIC_NLP_READY` | `false` | включает NLP-виджеты (облако слов, понятия, леммы) |

## Границы демонстрации

- Q&A, лайки, подписки и созданные публикации хранятся **в памяти BFF** и
  обнуляются при перезапуске контейнера.
- Синтетический корпус детерминирован: перезапуск даёт те же 218 публикаций и те же
  графики.
- Поиск работает на мок-движке `search.MockEngine`. Реализация C++ подключается
  заменой одной реализации интерфейса `search.Engine` (`Name()` возвращает имя
  движка, `Search` и `Suggest` — результаты):

  ```go
  type Engine interface {
      Search(ctx context.Context, q Query) (Result, error)
      Suggest(ctx context.Context, prefix string, limit int) ([]domain.Suggestion, error)
      Name() string
  }
  ```

  Точка сборки — `bff/cmd/server/main.go`, переменная `engine`.

- Ошибки API отдаются единым конвертом `{error:{code,message,details,request_id}}`,
  в заголовке ответа всегда есть `X-Request-ID`.

## Документация контракта

`CONTRACT.md` описывает все эндпоинты BFF по группам (каталог, поиск, публикации,
авторы, аналитика, Q&A, подписки, служебные), поля ответов, виджеты дашборда и
правила пометки источников.
